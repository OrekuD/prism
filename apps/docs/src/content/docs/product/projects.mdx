## Creating a project

From the projects page, pick the owning team and enter a name. The server:

1. checks your session and your permission on the team
   (`cannot_create_project` otherwise);
2. generates a unique slug;
3. inserts the project;
4. creates the project's analytics key
   (`pr_` + 32 hex characters) in `project_api_keys`.

Creating a project requires a **verified email address** — the product API
returns `email_not_verified` (the dashboard shows the verification banner
instead of an error) until you verify.

## Project pages

| Page | Shows |
| --- | --- |
| Summary | Overview metrics and charts for a chosen duration |
| Events | The latest 200 events for the project, newest first |
| Realtime | Live map of sessions as they start |
| Settings → General | Rename, and delete the project |
| Settings → API keys | The project's analytics key |

## Renaming and deleting

Rename via `PATCH /api/v1/projects/:projectId` (permission-checked). Delete
via `DELETE /api/v1/projects/:projectId`; deletion removes the project row —
take care: **deletion is not reversible** and the analytics store is not
garbage-collected for deleted projects today.

## Access rules

Project access is derived from team membership:

- Team owners and members with admin permission can create projects in the
  team.
- Reading a project requires team membership; unauthorized reads return
  `project_not_found` (no existence leak).
- The realtime WebSocket additionally verifies ownership/membership through
  the service JWT (see [Realtime](/product/realtime/)).
