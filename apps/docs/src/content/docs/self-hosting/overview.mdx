## What you get

A single-origin deployment: one public URL serves the dashboard, the product
API, analytics ingestion, realtime WebSocket, and uploaded files. No
per-service URLs, no outbound network access at runtime, no telemetry, no
account requirement.

## Services

| Service | Image | Role | Required |
| --- | --- | --- | --- |
| `db` | postgres:16 | Product database: users, teams, projects, keys | ✅ |
| `migrate` | prism-api | Forward-only migrations, runs before `api` | ✅ |
| `api` | prism-api | Product API (auth, teams, projects, setup) | ✅ |
| `sqld` | libsql | Analytics store (sessions, events) | ✅ (bundled) |
| `analytics` | prism-analytics-api | Ingestion + realtime WebSocket | ✅ |
| `web` | prism-web | nginx: static dashboard + single-origin proxy | ✅ |

Only `web` is exposed to the host (`PUBLIC_PORT`); `db` additionally binds
`127.0.0.1:POSTGRES_PORT` for host-side tooling.

## Storage

| Store | Backing | Persistence |
| --- | --- | --- |
| Product database | `pgdata` named volume | backups via `pg_dump` |
| Analytics store | `sqlddata` named volume | volume snapshots |
| Uploads | `uploads` named volume | volume snapshots (local driver) |

## Sizing

The stack is lightweight for evaluation: PostgreSQL 16, a Node API, and a
libSQL store all fit comfortably on a 1–2 vCPU / 2 GB host for small
traffic. Budget more for the analytics store as session volume grows — the
store is the main write path.

## Requirements

- Docker with Compose v2.
- A domain for production (TLS termination in front of `web`); local
  testing works on `http://localhost:3000`.
- Secrets: `JWT_SECRET_KEY` (32+ chars), `SETUP_TOKEN` (16+ chars), a
  `POSTGRES_PASSWORD`.
