## Write keys are public

Project analytics keys are embedded in public JavaScript. The model assumes
they leak and confines them to a write-only role (sessions/events for their
own project). Keys cannot read data or manage anything. See
[API keys](/product/api-keys/).

## Dashboard sessions

- HTTP-only, SameSite=Lax cookies, `prism` prefix (`prism.session_token`);
  `Secure` in production.
- Credentialed CORS only for allowlisted origins: `CLIENT_URL` +
  `CORS_ALLOWED_ORIGINS`. Development additionally trusts localhost ports;
  production is exact-match only.
- `/api/auth/*` is rate-limited to 20 requests/minute/IP.

## Service JWTs (realtime)

- RS256, issuer `prism`, audience `prism-analytics`, short-lived.
- Verified against `{BASE_URL}/api/auth/jwks`; keys rotate every 30 days
  with a 7-day grace overlap.
- The subject must be an active user **and** a member of the team owning the
  project. Client-supplied user ids are never trusted.

## CORS boundaries

| Boundary | Policy |
| --- | --- |
| Ingestion (`/api/v1/analytics/*`) | Any origin (public write keys) |
| WebSocket `/ws` | Any origin (JWT-authenticated) |
| Auth + management (`/api/auth/*`, `/api/v1/*`) | Allowlisted origins only, credentials enabled |
| Static dashboard + docs | Same-origin by construction |

## Rate limits

| Surface | Limit | Scope |
| --- | --- | --- |
| Ingestion | 120 req/min | per client IP, in-memory |
| WebSocket upgrades | 30/min | per client IP, in-memory |
| Auth | 20 req/min | per client IP, in-memory |
| Setup endpoint | 5 req/15 min | per client IP, in-memory |

All are per-process; multi-replica deployments should add a shared limiter.

## Stored data

- Product database: accounts (email, hashed passwords via Better Auth),
  teams, memberships, projects, keys, profiles.
- Analytics store: sessions (IP, referrer, location, geo, agent-derived
  fields) and events (name + structured data).
- Uploads: avatar images.
- Passwords are hashed; the JWT secret and setup token are never logged or
  exposed via config endpoints.

## Optional integrations

Every integration is opt-in and off by default in self-hosting: SMTP/Resend
mail, IP geo enrichment, S3/ImageKit storage, GitHub/Google sign-in. The
hosted deployment enables the ones Prism operates.

## Responsible disclosure

Security issues: **do not open a public issue**. Report privately to the
maintainers via GitHub (the repository is `OrekuD/prism`) — private
advisories or direct contact are preferred. Include the affected version,
a minimal repro, and impact. Public disclosure is expected after a fix is
released.
