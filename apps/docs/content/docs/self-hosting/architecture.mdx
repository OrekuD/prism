The default stack is a single public origin backed by two application
services and two data stores.

```text
Browser application
       |
       | events and identity operations
       v
+--------------------- public Prism origin ----------------------+
|                                                                 |
|  Web / nginx                                                    |
|  ├── dashboard assets                                           |
|  ├── /api/v1/* and /api/auth/* ───────────> Product API         |
|  ├── /api/v2/ingest ──────────────────────> Analytics API       |
|  ├── /ws ─────────────────────────────────> Analytics API       |
|  └── /files/* ─────────────────────────────> Product API        |
|                                                                 |
+-----------------------------------------------------------------+
                |                              |
                v                              v
        PostgreSQL 16                    libSQL / sqld
   accounts, teams, projects,       events, sessions, people,
    keys, auth, configuration       identities, and traits
                |
                v
      local uploads volume or
     configured external storage
```

## Services

- **web** — the only public service in the default stack. nginx serves
  the dashboard assets and routes API traffic to the right backend.
- **api** — the product API: authentication, accounts, teams, projects,
  setup, uploads, and management reads.
- **analytics** — the analytics API: ingestion (`/api/v2/ingest`) and
  realtime WebSocket delivery (`/ws`).
- **migrate** — runs forward-only PostgreSQL migrations before the
  product API starts.
- **db** — PostgreSQL 16 for product and authentication data.
- **sqld** — libSQL for analytics data: events, sessions, people,
  identity links, and traits. The analytics API applies its own
  migration journal at startup.
- **docs** — the documentation site; optional and isolated from the
  application network.

## Boundaries

- The product API reads the analytics store for dashboard queries; the
  analytics API never touches PostgreSQL.
- The default Docker network is internal; only `web` is published.
- Forwarding headers are trusted only for the bundled nginx, which
  overwrites `X-Forwarded-For` with the real peer address.
- Analytics keys are public and write-only; dashboard access uses
  HTTP-only cookie sessions and short-lived service JWTs for the
  WebSocket.
