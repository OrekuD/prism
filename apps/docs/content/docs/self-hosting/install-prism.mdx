This page installs Prism either as a single-host Docker Compose stack or as a split deployment with the analytics ingestion API on Render (free tier) via `render.yaml` at the repo root. Both create the first owner account the same way.

## Prerequisites

- Docker and Docker Compose on a Linux host.
- Generated secrets for PostgreSQL, session signing, and first-owner
  setup (a secrets generator such as `openssl rand` is fine). The
  analytics store token can stay empty for the bundled local `sqld`.
- A domain pointing at the host with TLS termination in front of the
  `web` service for anything beyond localhost.

## 1. Get the deployment files

The deployment files live in the repository: `deploy/compose.yml` + `deploy/compose.env.example` for the full single-host stack, and `render.yaml` (repo root) for the analytics API alone on Render. For Compose, copy `deploy/compose.env.example` to `deploy/compose.env` on your host and fill it in; for Render, create a Blueprint from `render.yaml` and fill the three prompted secrets (`TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `DATABASE_URL`). `AUTH_BASE_URL` is pre-set to the hosted product API.

## 2. Configure the environment

At minimum set (the Compose file builds `DATABASE_URL`,
`CLIENT_URL`, and the same-origin `AUTH_BASE_URL` from these — setting
those derived values yourself has no effect):

```sh
# PostgreSQL (Compose builds DATABASE_URL from these)
POSTGRES_USER=prism
POSTGRES_PASSWORD=CHANGE_ME
POSTGRES_DB=prism

# Session signing (minimum 32 characters)
JWT_SECRET_KEY=CHANGE_ME_GENERATED

# This deployment's public origin
PUBLIC_URL=https://prism.example.com

# First-owner setup token (minimum 16 characters)
SETUP_TOKEN=CHANGE_ME_GENERATED
```

Generate secrets with `openssl rand -hex 32`. The API refuses to boot
with missing or weak required values and names the offender in its log.
Optional groups — mail, OAuth providers, S3 storage, geo enrichment,
retention — are listed in
[Configure and operate](/docs/self-hosting/configure-and-operate).

## 3. Start and migrate

```sh
docker compose --env-file deploy/compose.env -f deploy/compose.yml up -d --build
```

The `migrate` service applies forward-only schema migrations before
the API starts (it runs automatically via `depends_on`). Migrations
are idempotent — applied ones are skipped. Re-run `migrate` after
upgrades.

## 4. Verify health

```sh
curl http://localhost:3000/health/live
curl http://localhost:3000/health/ready
```

`live` proves the process is up; `ready` checks the product database.
Both must pass before you continue. (The analytics-store check lives
on the analytics service's own `/health/ready` and is not reachable
through the public origin.)

## 5. Create the first owner

Open `https://your-domain/setup` and claim ownership with
`SETUP_TOKEN`. Treat the token as a secret: the claim is
constant-time-compared and rate-limited, and the setup endpoint closes
permanently after the first successful owner. Remove the variable
afterwards.

If the setup wizard cannot reach the API, check
`curl http://localhost:3000/api/v1/config` and the `api` container logs
first — most first-boot failures are proxy or database configuration.
