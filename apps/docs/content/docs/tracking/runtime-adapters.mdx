<SectionLabel label="ADAPTER AUTHORING" />

`@prism-analytics/core` is runtime-neutral: no DOM, Node, React Native, or provider
globals, and zero import-time side effects. Every platform reaches it
through ONE injected seam — the `PrismRuntimeAdapter`:

```ts
interface PrismRuntimeAdapter {
  readonly name: string;                 // capability identifier
  now(): number;                          // epoch ms
  createId(): string;                     // collision-resistant IDs
  readonly transport: PrismTransport;     // batch POST (headers carry auth!)
  readonly storage?: PrismStorage;        // optional durable queue/identity
  schedule(delayMs: number, cb: () => void): () => void; // timers with cancel
  readonly context: PrismRuntimeContext;  // normalized, minimal, JSON-safe
  readonly lifecycle?: PrismLifecycle;    // foreground/background/before-unload
}
```

## The rules that keep adapters thin

1. **Never implement Prism semantics in the adapter.** No queueing,
   consent, sanitization, session, batching, or retry logic — the core
   owns all of it. If you are writing a retry loop in an adapter, you are
   off the pattern.
2. **Forward `request.headers` unchanged.** The core supplies
   `authorization: Bearer <key>` and `content-type`; the adapter must not
   remove or log them, and must never add an unauthenticated fallback
   (a `sendBeacon` that cannot carry headers must not be used).
3. **Keep context minimal and JSON-safe.** The core validates and
   sanitizes an allowlisted set of fields (platform, kind, screen size,
   locale, timezone, app/device metadata). No user-agent copies, no DOM
   content, no form values.
4. **Schedulers must return a real cancel.** The core's bounded retry
   loop and shutdown depend on being able to cancel pending timers —
   including chunked long delays.
5. **Storage is optional but all-or-nothing.** If you provide storage,
   queue snapshots and (with `persistent` identity) the anonymous ID flow
   through it. Denied/quota-failing storage should degrade to the
   core's in-memory behavior, never crash.
6. **Lifecycle is best-effort.** Unload events are unreliable; the core
   treats a lifecycle flush as a bounded request, and stale-session
   handling stays authoritative server-side.

The reference implementations are `@prism-analytics/browser` (platform seam) and
`@prism-analytics/react` (framework binding — a zero-effect provider over an
already-created client). Vue/React Native/Node adapters follow the same
pattern: translate platform primitives, delegate semantics.
