## Shape

`POST /api/v2/ingest` with a Bearer analytics key (the SDK constructs the
batch envelope for you):

```json
{
  "schemaVersion": 2,
  "sentAt": 1723456789012,
  "sdk": { "name": "@prism/core", "version": "0.0.1" },
  "events": [
    {
      "schemaVersion": 2,
      "eventId": "client-generated-id",
      "type": "track",
      "occurredAt": 1723456789000,
      "sessionId": "client-owned-session",
      "anonymousId": "anonymous-identity",
      "name": "button-click",
      "properties": { "label": "signup" },
      "context": { "platform": "browser", "kind": "web" }
    }
  ]
}
```

## Response

Per-event results, keyed by index and ID — never echoing submitted
properties or values:

```json
{
  "ok": true,
  "results": [
    { "index": 0, "id": "client-generated-id", "status": "accepted" }
  ]
}
```

`duplicate` means a replayed event ID (transport retries are idempotent);
`rejected` carries a coarse reason (`invalid-name`, `invalid-properties`,
`invalid-timestamp`, `unsupported-type`, `too-large`).

## Validation

Names are non-empty, ≤ 128 characters, no control characters. Properties are
strict JSON values — non-finite numbers, dates, class instances, accessors,
cycles, and `__proto__`/`constructor`/`prototype` keys are rejected. The
shared ceilings (batch 50 / request 512 KiB / event 32 KiB / depth 12 /
strings 10 000) are enforced identically by the SDK and the server, so an
official-SDK event is never rejected as oversized.

## Server-side protection

Direct HTTP clients are untrusted: the server validates the same rules,
sanitizes credential keys (`[REDACTED]`), enforces per-request byte limits
while streaming (413), and applies per-IP plus event-weighted per-project
quotas (429 + Retry-After).
