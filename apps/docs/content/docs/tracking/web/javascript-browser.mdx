<SectionLabel label="PACKAGE: @prism-analytics/core" />

The core is runtime-neutral: no DOM, Node, or framework globals. It is built
as CJS + ESM with TypeScript declarations (`tsup`).

```ts
import { createPrismClient } from "@prism-analytics/core";
```

## `createPrismClient(options)`

The async factory resolves to a READY client. One options object — no
positional arguments:

| Field | Type | Description |
| --- | --- | --- |
| `sourceKey` | `string` | Source ingestion key (publishable, write-only) |
| `endpoint` | `string` | Ingestion origin chosen at runtime — never compiled in |
| `runtime` | `PrismRuntimeAdapter` | Injected transport/storage/time/scheduler/lifecycle seams |
| `collection.initialState` | `"pending" \| "granted" \| "denied"` | Consent state machine |

The [Node example](../../start/overview) shows a complete fake runtime. Browser
apps use the runtime adapter from `@prism-analytics/browser` (or a small inline runtime
until it ships).

Invalid caller input throws a specific validation error. Consent, shutdown,
and queue-capacity conditions return discriminated `dropped` results — never
silent no-ops.

## `track(name, properties?)`

```ts
const result = prism.track("button-click", { label: "signup" });
// { status: "queued", eventId } | { status: "dropped", reason }
```

`queued` means accepted locally. Delivery is never part of the call stack —
background failures surface through the diagnostics subscription and through
rejected `flush()`/`shutdown()` promises.

## Sessions

```ts
const handle = prism.startSession({ properties: { plan: "pro" } });
handle.end(); // emits session_ended (second call → not-active)
```

Client-owned session IDs; no server round-trip before events are accepted.

## Consent

```ts
prism.track("early"); // dropped when initialState is "pending" or "denied"
await prism.setCollectionState("granted");
```

Withdrawing consent clears the queue, deletes the persisted anonymous ID,
closes the active session, and cancels in-flight delivery — nothing
collected before a withdrawal is ever transmitted.

## Delivery semantics (honest)

- `queued` is **not** delivered: `track()` accepts the event into the local
  queue and returns immediately; delivery happens on the batch threshold,
  the background interval, lifecycle events, or an explicit `flush()`.
- `flush()` **can reject** on delivery failure (network, 429/5xx) — the
  batch stays queued and retries with exponential backoff; a valid
  `Retry-After` is honored as a minimum. Rejections also surface through
  the diagnostics subscription (`onDiagnostic`).
- A `queue-full` result means the configured local ceiling was reached —
  the event was NOT queued.
- Batches are idempotent by client-owned event IDs: transport retries
  become `duplicate` server-side, never double rows.
- `shutdown({ timeoutMs })` performs one bounded final flush and stops all
  timers/listeners — post-shutdown captures return `dropped` explicitly.
