The project dashboard shows what Prism has captured for one project:
per-day session counts, device splits, recent events, live sessions, and
people. Every metric on the dashboard is backed by a bounded database
query against the analytics store — no screen loads an unbounded project
into memory.

## Summary metrics

The summary page shows three headline numbers for the selected period.

- **Sessions** — accepted `session_started` events. The label is
  deliberate: Prism does not call this "Visitors," because cross-session
  visitor uniqueness does not exist yet.
- **Desktop / Mobile** — the session split by the context `kind` field.
  Unknown kinds count as desktop.
- **Events** — the number of rows in the bounded recent-events list, not
  a project-wide total.

The activity chart plots per-day session counts, split by device, over
the selected period.

## What is exact and what is bounded

Exact numbers come from the API: the [honest totals](/docs/reference/api/analytics-queries)
count event occurrences, unique resolved people, unique anonymous
identities, and sessions as four distinct metrics.

Dashboard screens show bounded recent lists. The events page returns the
latest events, and the realtime page shows live sessions only. Browser and
OS rankings are not shown because the v2 model does not collect that
data.

## People

Identified people appear on the **People** page after an explicit
`identify()` call. See [People and profiles](/docs/analytics/people) for
the full behavior.
