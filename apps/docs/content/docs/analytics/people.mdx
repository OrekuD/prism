The **People** page lists the resolved analytics subjects of a project. A
person appears only after an explicit `identify()` call with a
developer-supplied external ID — Prism never invents people from page
views or device fingerprints.

## The people list

The table shows one row per person with:

- an opaque person identifier (a deterministic hash, not an email or
  username);
- trait keys (values are hidden by default — reveal them deliberately);
- distinct session count;
- event occurrence count;
- linked identity count (external IDs plus anonymous IDs);
- last-seen time.

Pagination is keyset-based; each page is a bounded query. The search box
matches the **exact external ID** only. Broad enumeration is intentionally
unavailable: there is no prefix, fuzzy, or partial matching, and search
never scans trait values.

## Person profiles

Open a person to see:

- current traits (redacted until you reveal them);
- every linked external and anonymous identity;
- first and last seen times;
- a chronological event timeline.

## Export

**Export person data** downloads a JSON file with documented analytics
data only: identity references, traits, sessions, and events. The file
never contains project keys, auth tokens, raw IP data, or other people's
information. Export is project-scoped and team-authorized.

## Deletion

**Delete person** permanently removes the person's identity links,
traits, sessions, and events. The action requires typing `delete` to
confirm, and the API requires `?confirm=true`.

Deletion removes identity links first. A later `identify()` with the same
external ID creates a NEW person with a clean slate — deleted history
never silently returns.
