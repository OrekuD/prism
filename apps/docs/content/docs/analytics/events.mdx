An event is one explicit `track()` call accepted by the ingestion
service. Events are immutable: the stored row never changes after
acceptance.

## What an event contains

- a client-generated event ID (idempotent replay protection);
- the event name;
- typed properties (JSON-safe values only);
- `occurredAt` (client clock) and `receivedAt` (server clock);
- the session and anonymous IDs at capture time;
- the developer-supplied external user ID when the caller identified;
- the derived person association;
- the batch SDK metadata.

Properties are stored as JSON text and decoded at the API boundary into
typed values; malformed stored JSON is quarantined to `null` rather than
breaking a response.

## The recent-events view

The project's **Events** page lists the latest events for the project,
newest first. The list is bounded — it is not a project-wide total.
Instrumentation guidance lives in [Track events](/docs/tracking/events),
and programmatic filters and breakdowns live in
[People and analytics queries](/docs/reference/api/analytics-queries).

## Deletion

Events are removed by person deletion, by retention, or with their
project. See [Person data, export, and deletion](/docs/privacy-security/person-data)
and [Data retention](/docs/privacy-security/retention).
