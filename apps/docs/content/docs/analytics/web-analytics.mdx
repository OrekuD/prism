Web analytics shows page-view traffic for the Web sources in a project:
trends, top pages, referrers, campaigns, locations, and technology. It
is a separate module from the event stream — page views are captured
automatically by the browser SDK and aggregated server-side into fixed
reports.

## Setup

Web analytics requires two things: a Web source and a browser SDK with
page tracking enabled.

1. Create a source with the **Web** platform under **Sources**. Page
   views from non-Web sources are rejected at ingestion.
2. Enable page tracking in the browser SDK:

   ```ts
   import { createBrowserClient } from "@prism-analytics/browser";

   const client = createBrowserClient({
     endpoint: "https://prism.example.com/api/v2/ingest",
     sourceKey: "psk_...",
     pageViews: { mode: "history" },
   });
   ```

   In `history` mode the SDK captures a page view on every pushState,
   replaceState, and popstate navigation. Use `mode: "manual"` and call
   `client.pageViews.capture({ path })` when your router needs explicit
   control.

3. In React, render page views with the hook instead of manual capture:

   ```tsx
   import { PrismProvider, usePrismPageView } from "@prism-analytics/react";

   function App() {
     usePrismPageView({ path: location.pathname });
     return <Outlet />;
   }
   ```

   The hook requires `mode: "manual"` on the client and captures once
   per path change, including under React Strict Mode.

Page views respect the SDK's consent state: nothing is captured or
retained until collection is granted.

## The dashboard

Open **Web analytics** in the sidebar. The page has five sections.

- **Metric strip** — page views, unique visitors, sessions, bounce rate,
  and views per session for the selected range. Bounce rate stays empty
  until sessions have completed the 30-minute window; it is never
  rendered as zero.
- **Trend** — page views, visitors, or sessions per bucket. Ranges up to
  26 hours bucket hourly, up to 91 days daily, and longer ranges weekly.
- **Top pages** — views, visitors, and bounce rate per path, or
  entrances on the **Entry pages** tab. Click a row to filter the whole
  page to that path.
- **Referrers, Campaigns, Locations** — sessions by external referrer
  host (with an explicit Direct row), by UTM source/medium/campaign, and
  by country, region, or city.
- **Technology** — browsers, operating systems, devices, viewport
  buckets, and primary languages.

## Ranges, comparison, and filters

Pick a range from 24 hours to 12 months, or choose **Custom** and enter
exact dates (up to 366 days). **Compare** overlays the previous
equal-length period on the trend and shows the change on each metric.
When no prior data exists, the dashboard says so instead of showing a
misleading percentage.

Filters narrow every panel: a specific Web source, an allowed host,
human-only or bot-inclusive traffic, and the selected page path.

## Privacy

Web analytics is built to avoid collecting what it does not need.

- Only the page host, path, and optional title are captured — never the
  full URL, query string, or hash.
- Referrers are reduced to the external host only. Same-host referrers
  are excluded from rankings.
- Campaigns use only the allowlisted UTM parameters.
- The raw user agent and IP address are never stored. Technology comes
  from a server-side parser, and coarse geography is derived at
  ingestion and dropped.
- Region and city rows with fewer than 5 sessions collapse into
  "Other", server-side, so suppressed groups cannot be recovered by
  filtering.

Page views are deleted with their person, with their project, and by
retention like any other event data.

## Troubleshooting

- **The page says "No Web sources in this project."** Create a source
  with the Web platform. Server and mobile sources do not contribute.
- **No data appears.** Check that the SDK client was created with a
  `pageViews` config — without it the client captures no page views.
  Confirm the page host matches one of the source's allowed origins;
  mismatches are rejected at ingestion.
- **Bounce rate is empty.** No session has completed the 30-minute
  inactivity window yet. It fills in as sessions complete.
- **Locations are sparse.** Geography is derived at ingestion from the
  client IP. Events delivered more than 15 minutes late are accepted
  without geography.
