One reference entry point for Prism's public packages and every numeric
ceiling. Feature behavior lives on the feature pages; this page is the
canonical home for limits, so numbers are stated once. Detailed symbol
references for each package are linked at the end — they are searchable
but kept out of the primary sidebar.

## Packages

- `@prism-analytics/core` — the runtime-neutral engine: queue, consent,
  validation, sanitization, sessions, identity. No platform globals.
- `@prism-analytics/browser` — browser transport, storage, lifecycle,
  page views, and the browser error reporter.
- `@prism-analytics/react` — provider and hooks over a ready Browser
  client, plus the error boundary.
- `@prism-analytics/node` — Node error reporting for server processes.

## Events and properties

- Event names: non-empty, at most 128 characters, no control
  characters. The `$prism_` prefix is SDK-reserved —
  `track("$prism_*")` throws; only `prism.events.*` and build-in
  automatic events can create it.
- Standard Events: the `prism.events` namespace (25 helpers) rides the
  same delivery lane (`type: "track"`, same queue, consent, retry, and
  `CaptureResult`). Each helper owns a protected `$prism_*` name and an
  exact `$standard: { schemaVersion: 1, key, data }` shape. The
  ingestion API rejects unknown protected names with
  `unknown-reserved-event` and malformed Standard Events with
  `invalid-standard-event`. See
  [Standard Events](/docs/features/standard-events) for the catalog and
  limits.
- Actor override: `prism.events.signUp({ method }, { userId })` — the
  per-call `{ userId }` applies only to that event and doesn't mutate
  global identity. `signUp`, `login`, and `logout` require an identified
  user (via `identify()` or the actor) and throw otherwise.
- Properties and traits: strict JSON values only — no functions,
  symbols, bigint, non-finite numbers, dates, class instances,
  accessors, or cycles. Keys `__proto__`, `constructor`, and
  `prototype` are rejected.
- Depth at most 12; strings at most 10,000 characters.
- Credential-like keys (`password`, `token`, `apiKey`,
  `authorization`, and similar) are redacted server-side.
- Trait keys: 1–128 characters, no control characters.
- Standard Event limits: stable token `1-64` chars
  (`^[a-z][a-z0-9._-]*$`), opaque analytics ID `1-128`
  (`^[A-Za-z0-9][A-Za-z0-9._:-]*$`), currency exactly `3` uppercase
  letters, money a non-negative safe integer in minor units, count and
  duration non-negative, effective timestamp a positive epoch-ms
  integer, rating `1-5`, trial duration `1-3660` days. Unknown keys,
  `undefined`, non-finite numbers, and provider payloads are rejected.

## Sizes and batching

| Ceiling | Value |
| --- | --- |
| Events per batch | 50 |
| Request body | 512 KiB (enforced while streaming) |
| Single event | 32 KiB |
| SDK queue | 1,000 events / 1 MiB |
| SDK batch bytes | 256 KiB |
| Error report | same event ceilings; dedupe window 1,000 ms default |
| Page views | 50-row ranking ceiling; 13-month dashboard range |

All ceilings are shared between the SDK and the server: an
official-SDK event is never rejected by ingestion for rules the SDK
already enforces.

## Time and delivery

- `occurredAt` may not exceed 24 hours of future skew; unreasonably old
  timestamps are rejected with `invalid-timestamp`.
- SDK defaults: request timeout 10 s, flush interval 10 s, 5 retries
  with exponential backoff and jitter.
- Page-view Web sessions expire after 30 minutes of inactivity; page
  views delivered more than 15 minutes late are accepted without
  geography.

## Queries and rate limits

- People page size: default 50, max 100.
- Activity: default 200 events. Filtered events: default 200, max 500.
- Breakdowns: at most 100 keys. Person export: bounded to 500 events.
- Ingestion: 120 requests per minute per IP plus an event-weighted
  per-project allowance; exceeded requests get `429` with
  `Retry-After`.
- WebSocket upgrades: 30 per minute per IP.

## Runtime adapters

Every platform reaches the core through one injected seam, the
`PrismRuntimeAdapter`: `now()`, `createId()`, a `transport` for batch
POSTs, optional `storage`, a cancellable `schedule()`, minimal
JSON-safe `context`, and optional `lifecycle` signals.

The rules that keep adapters thin:

1. Never implement Prism semantics in an adapter — queueing, consent,
   sanitization, sessions, batching, and retries belong to the core.
2. Forward request headers unchanged; never add an unauthenticated
   fallback transport.
3. Keep context minimal and JSON-safe — no user-agent copies, DOM
   content, or form values.
4. Schedulers must return a real cancel function.
5. Storage is optional but all-or-nothing; failing storage degrades to
   in-memory behavior, never crashes.
6. Lifecycle is best-effort; unload flushes are bounded requests.

The reference implementation is `@prism-analytics/browser`.
