Prism links activity to **people**. A person starts as an anonymous
identity generated by the SDK and becomes known when you call
`identify()` with your own user ID. This page covers the identity model,
the SDK operations, and the People dashboard, including export and
deletion.

## Anonymous identity

Every client starts with an anonymous ID. With the default persistence
mode it survives reloads in the same browser profile; choose a stricter
mode through the client's `collection.anonymousPersistence` option.
All pre-identify events attach to this anonymous identity.

## `identify(userId, traits?)`

```ts
const result = await prism.identify("user_123", { plan: "pro" });
// { status: "queued", opId, userId, anonymousId } | { status: "dropped", reason }
```

One ordered operation: the current anonymous identity links to the
external ID, traits apply, and immediately-following `track()` events
carry the user ID. The operation queues and retries idempotently.

- **Multi-device**: one user ID may link many anonymous IDs. Events
  resolve to the person by user ID; pre-identify history links through
  the anonymous identity. Historical events are never rewritten.
- **Shared devices**: an anonymous identity is never silently re-linked
  to a second person. `identify(B)` after `identify(A)` rotates to a
  fresh anonymous context — two known people are never merged.
- **Traits**: set or update with `identify(userId, traits)`; remove with
  `identify(userId, { $unset: ["old_key"] })`.

## `reset()`

```ts
await prism.reset(); // logout semantics
```

Closes the session, clears the known identity, rotates the anonymous
ID, and clears queued identify operations and all global-property
scopes. The next user on a shared device never inherits the previous
user's context. Queued events keep their immutable identity context.

## What Prism never captures

The SDK does not collect emails, names, or any profile field you do not
pass explicitly. Traits are developer-supplied JSON values, sanitized
like event properties.

## The People dashboard

Identified people appear on the project's **People** page after an
`identify()` call — anonymous-only traffic does not create people rows.

- The **people list** shows each person's external ID, traits, first and
  last seen, and event volume, with search and filters.
- A **person profile** shows identity links (anonymous IDs and external
  IDs), traits, and the person's event history.
- **Export** produces a complete copy of the person's data — identity
  links, traits, sessions, and events — for data-portability requests.
- **Delete person** permanently removes identity links, traits,
  sessions, and events. The action requires typing `delete` to confirm.
  A later `identify()` with the same external ID creates a new person
  with a clean slate — deleted history never silently returns.

## Consent and identity

`identify()` respects the consent state machine: with collection denied,
identify operations are dropped. See
[Consent and privacy](/docs/configuration/consent-and-privacy) for the
state machine and persistence choices.
