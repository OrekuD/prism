Add Prism to your React Native app with Metro-safe transport, durable
storage, and lifecycle handling for foreground and background states.
You can track screen views, app sessions, and errors with the same
privacy controls as the browser SDK.

Use this guide to install the SDK, create a client, and verify your
first events. It covers Expo SDK 53 and React Native 0.79 with Hermes.

## Installation

Install the SDK. Prism works with Expo and bare workflows.

<InstallTabs pkg="@prism-analytics/react-native" />

This package requires `react` and `react-native` as peers. For
durable storage and navigation tracking, you can also install:

* `@react-native-async-storage/async-storage` version 2 for queue
  persistence and installation identity.
* `@react-navigation/native` version 7 for automatic screen tracking,
  or Expo Router.

## Create the client

Create the client once when your app starts, outside any component.
Keep the reference for the lifetime of the app.

```ts
import { createReactNativeClient } from "@prism-analytics/react-native";
import AsyncStorage from "@react-native-async-storage/async-storage";

export const prism = await createReactNativeClient({
  sourceKey: "psk_your_key",
  endpoint: "https://prism-analytics-api-gsmo.onrender.com",
  storage: AsyncStorage,
  collection: { initialState: "granted" },
  app: { version: "1.0.0", build: "1", environment: "production" },
});
```

Prism validates your options before it sends any data. It checks the
source key, endpoint, and app metadata. If validation fails, it throws
a clear error and sends nothing. If consent is denied or the queue is
full at runtime, `track` and `prism.events.*` return
`{ status: "dropped", reason }` instead of throwing.

```ts
prism.events.search({ category: "documentation", resultCount: 8 });
prism.events.share({ method: "email", contentType: "report" });
```

See [Standard Events](/docs/features/standard-events) for the full catalog.

When your app moves to the background, the SDK flushes queued events
and records foreground time. When it returns to the foreground, it
resumes the session. Change consent with
`prism.setCollectionState("granted")` or
`prism.setCollectionState("denied")`.

## Track screen views

Screen views power the Mobile analytics dashboard, including top
screens, releases, and OS breakdowns. Each view is a reserved
`$prism_screen_view` record.

Track a screen manually:

```ts
prism.screen("Home", {
  routePattern: "/home",
  previousScreen: "Login",
});
```

Prism validates the screen name. It must be present and 128 characters
or fewer.

You can also use the navigation adapters. They wrap this call for you:

* React Navigation 7
* Expo Router

Screen counts and foreground time aggregate by app session. Prism groups
views by screen name and route pattern for the dashboard.

## Understand app sessions and installations

Prism manages two concepts for mobile:

* **App sessions** group screen views and events with a 30-minute
  inactivity timeout. The SDK owns the lifecycle through `AppState` and
  `Dimensions`. You don't need to start or end sessions yourself.
* **Installations** identify a single install of your app. The SDK
  generates a random ID once and stores it under the key
  `prism:installation:${endpoint}:${sourceKey}`. It uses your
  `AsyncStorage` instance for durability. The server stores only a
  digested hash, never the raw ID.

## Add error tracking

Prism sanitizes JavaScript errors before it sends them, and it groups
them server-side. The React Native SDK reuses the browser error lane.

See [Error tracking](../features/error-tracking.mdx) for capture
options, deduplication, and the dashboard.
