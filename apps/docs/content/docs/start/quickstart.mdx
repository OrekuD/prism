This guide takes you from a fresh Prism account to a verified event on
your dashboard. It uses the hosted deployment. If you want to run Prism
on your own infrastructure, see
[Self-host Prism](/docs/self-hosting/self-host-prism) instead — the SDK
steps are identical once an instance is running.

## 1. Create your account

Sign up with email. Prism creates a personal **workspace** for you
automatically. A workspace owns members and projects.

## 2. Create a project and a Web source

A **project** is the unit of analytics: one set of events, sessions, and
people, and one realtime stream. Create one from the workspace
overview.

Inside the project, open **Sources** and create a source with the **Web**
platform. A **source** is one instrumented application. Web sources have
**allowed origins** — only browsers on those origins may ingest with the
source's key.

## 3. Copy the setup snippet

Open the source's **Setup** tab. It shows a ready-made snippet containing
your publishable source key (`psk_...`) and the ingestion **origin**
(bare origin like `https://prism-analytics-api-gsmo.onrender.com` — the
SDK appends `/api/v2/ingest` automatically). Copy the origin, not the
full ingest URL. Publishable keys are safe to embed in client code —
they can only write analytics data, and the project is derived from the
key on every request.

## 5. Initialize the client

For the hosted deployment, use
`https://prism-analytics-api-gsmo.onrender.com`. For a self-hosted
instance, use your `PUBLIC_URL`.

```ts
import { createBrowserClient } from "@prism-analytics/browser";

export const prism = await createBrowserClient({
  sourceKey: "psk_your_key",
  endpoint: "https://prism-analytics-api-gsmo.onrender.com",
  collection: { initialState: "granted" },
});
```

The factory is async and resolves to a ready client. It performs no
automatic side effects beyond wiring its own queue and storage.

## 6. Identify and capture a Standard Event

```ts
await prism.identify(user.id);
prism.events.signUp({ method: "email" });

const result = prism.track("report_exported", { format: "csv" });
// { status: "queued", eventId } | { status: "dropped", reason }
```

`track` and `prism.events.*` are synchronous. Invalid caller input (empty
name, invalid token, non-JSON properties, wrong Standard Event schema)
throws; consent, shutdown, and queue-capacity return a `dropped` result.
`queued` means accepted locally; delivery happens in the background. See
[Standard Events](/docs/features/standard-events) and
[Capturing events](/docs/features/capturing-events).

## 7. Verify it

Open the project's **Events** page in the Prism dashboard. Your event
appears within seconds of delivery. Start a session with
`prism.startSession()` and it shows up live on the **Live** page.
`startSession()` is also synchronous and returns a discriminated
result — `{ status: "started", session }` or
`{ status: "blocked", reason }` (consent pending/denied, an active
