`@prism-analytics/node` is the server SDK for Prism. It reports errors from Node processes into the Errors dashboard, and the runtime-neutral `@prism-analytics/core` engine handles event capture when you need it. This page covers server setup and lifecycle ownership.

## Installation

<InstallTabs pkg="@prism-analytics/node" />

Requires Node 18+ (`globalThis.fetch` and `crypto.randomUUID`).

## Creating the error reporter

`createNodeErrorReporter` is an async factory that resolves to a ready reporter. One options object, no positional arguments:

```ts
import { createNodeErrorReporter } from "@prism-analytics/node";

const errors = await createNodeErrorReporter({
  sourceKey: "psk_your_key",
  endpoint: "https://prism-analytics-api-gsmo.onrender.com",
  share: { client: prism },
  release: "api@2.1.0",
  environment: "production",
});
```

Invalid options throw a specific validation error before any network activity. Runtime conditions — consent denied, reporter shut down, queue full — return a discriminated `dropped` result from `captureException` instead of throwing.

## Capturing errors

```ts
// Direct capture — normalize any thrown value.
errors.captureException(err, {
  handled: false,
  context: { tags: { route: c.req.path } },
});

// Framework helper — never crashes request handling.
import { reportError } from "@prism-analytics/node";
app.onError((err, c) => {
  reportError(errors, err, { handled: false });
  return c.json({ error: "internal" }, 500);
});
```

- `captureException(value, options?)` normalizes `Error`, strings, or arbitrary rejected values into a report. Same-fingerprint reports within the dedupe window return `deduped`.
- A `beforeSend` hook can drop or redact a report before it queues.
- Sanitization strips sensitive-looking values before anything leaves the process.

## Process-level capture (opt-in)

The reporter does **not** install `uncaughtException` or `unhandledRejection` handlers by default — the application owns crash and restart policy. Opt in explicitly when you want Prism to observe unhandled failures:

```ts
import { captureProcessErrors } from "@prism-analytics/node";

const handle = captureProcessErrors(errors);
// later: handle.uninstall();
```

Flush-on-shutdown is best-effort via `beforeExit` / `SIGINT` / `SIGTERM`. The reporter's own `shutdown()` remains the deterministic close, with a bounded final flush. Call it where you tear down the process:

```ts
await errors.shutdown();
```

## Events in Node — Standard Events via createNodeClient

For product analytics from the server, use the Node analytics factory:

```ts
import { createNodeClient } from "@prism-analytics/node";

const prism = await createNodeClient({
  sourceKey: process.env.PRISM_SOURCE_KEY!,
  endpoint: process.env.PRISM_ENDPOINT!,
  collection: { initialState: "granted" },
});

// concurrency-safe: per-call actor, no global identity mutation
prism.events.subscriptionCancelled(
  { subscriptionId: subscription.analyticsId, planId: "pro_monthly" },
  { userId: user.id },
);
prism.events.purchase({
  transactionId: "order_2026_1042",
  valueMinor: 1299,
  currency: "USD",
});
```

`createNodeClient` is a thin wrapper over `createPrismClient` + `createNodeRuntime` with the same queue, batching, retry, and `flush()`/`shutdown()` lifecycle. It requires explicit `endpoint`, `sourceKey`, and `initialState`, uses a server source key (platform stays server-authoritative at ingestion), and must use the per-call `{ userId }` actor in concurrent handlers. See [Standard Events](/docs/features/standard-events) for the full catalog and [SDK API and limits](/docs/reference/sdk-api-and-limits) for the adapter contract.
