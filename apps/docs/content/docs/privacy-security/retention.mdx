Retention removes expired analytics data from the live store. It is
separate from person deletion and from backup retention.

## Live-store retention

`ANALYTICS_RETENTION_DAYS` controls how long analytics data lives:

- unset or `0` disables deletion (the default — no surprise data loss);
- a positive integer enables batched deletion of events older than that
  many days (by server `received_at`), plus their sessions, identity
  links, traits, and people.

The retention CLI runs against the analytics store:

```sh
yarn workspace prism-analytics-api retention --status   # config + counts
yarn workspace prism-analytics-api retention --dry-run  # what would be deleted
yarn workspace prism-analytics-api retention            # apply deletion
```

Deletion happens in one atomic write batch in dependency-safe order
(events first, people last), so a failure rolls back everything. The
output is redacted — counts only.

Schedule the apply command with cron or a job runner in self-hosted
deployments; there is no built-in scheduler.

## Person deletion

Person deletion (dashboard or API) removes one person's data on demand
and is independent of the retention window. See
[Person data, export, and deletion](/docs/privacy-security/person-data).

## Account deletion

Account deletion removes product accounts, teams, and projects. Analytics
data for deleted projects follows the retention rules of the store.

## Backups

Retention deletes data from the LIVE store only. It does not rewrite
existing backups. Keep backup retention separate from
`ANALYTICS_RETENTION_DAYS`, and verify restore drills regularly — see
[Back up and restore](/docs/self-hosting/operations/backup-restore).
