This page describes the privacy model behind the SDK consent calls. For
the call sequence, see [Manage consent](/docs/tracking/consent).

## Collection states

Every client starts in an explicit state — `pending`, `granted`, or
`denied` — chosen by the caller. There is no implicit default.

- `pending` and `denied` drop captures; nothing is queued or transmitted.
- Withdrawal (`denied`) additionally clears the queue, the anonymous
  identity, the known identity, global properties, and queued identify
  operations, and cancels in-flight delivery.

## Anonymous identity persistence

`anonymousPersistence` controls where the anonymous ID lives:
`none`, `session` (client lifetime), or `persistent` (survives launches,
requires storage). The ID is an opaque token — never an email, username,
or device identifier — and it is deleted on withdrawal. A re-grant
creates a fresh ID; the pre-withdrawal identity is never restored.

## Project and endpoint isolation

Stored state is namespaced by endpoint origin and project identity. A
persisted queue from one endpoint is never delivered to a different
instance, and two projects on one origin keep separate queues. The
anonymous ID is origin-scoped: one identity per origin, shared across
projects of the same instance.

## No cross-site identity

Prism does not track users across origins. Identities, queues, and
properties are scoped to the origin where the SDK runs.
