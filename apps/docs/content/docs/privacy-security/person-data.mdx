Person data is developer-supplied: Prism stores only the external IDs,
anonymous IDs, traits, sessions, and events associated with an explicit
`identify()` call.

## Export

**Export person data** (dashboard) or `GET
/api/v1/projects/:slug/people/:personId/export` returns documented
analytics data only:

- identity references (external and anonymous IDs);
- current traits;
- sessions (IDs, start, last seen);
- events (bounded, newest first).

The export never contains project keys, auth tokens, raw IP data, or
other people's information. It is project-scoped and team-authorized —
the person must belong to a project you can access.

## Deletion

Deletion is a destructive, confirmed operation. In the dashboard you must
type `delete`; the API requires `?confirm=true`. It removes, atomically
and in dependency-safe order:

1. identity links;
2. traits;
3. sessions and events;
4. the person row.

Repeated deletion is a safe no-op. Because links are removed first, a
later `identify()` with the same external ID creates a NEW person with a
clean slate — deleted history never silently returns.

Deletion removes raw events rather than anonymizing them. Prism chooses
privacy over aggregate accuracy for person deletions; counts on other
screens change accordingly.
