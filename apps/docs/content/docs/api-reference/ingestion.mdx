<SectionLabel label="Analytics boundary" />

Base URL: `{ANALYTICS_ORIGIN}/api/v2/ingest` — hosted analytics origin, or
your self-hosted origin (the same public origin that serves the app).
Authentication: `Authorization: Bearer <project analytics key>` on every
request. No cookies. The key is public by design (write-only, ingestion-only).

CORS: the analytics API answers **any origin** — the browser SDK posts
cross-origin from customer sites.

## `POST /api/v2/ingest` — submit a batch

**Auth:** Bearer project analytics key · **Limits:** 120 requests/minute/IP
plus an event-weighted per-project quota (429 + Retry-After on exceed)

```json
{
  "schemaVersion": 2,
  "sentAt": 1723456789012,
  "sdk": { "name": "@prism/core", "version": "0.0.1" },
  "events": [
    {
      "schemaVersion": 2,
      "eventId": "evt-01",
      "type": "track",
      "occurredAt": 1723456789000,
      "name": "button-click",
      "properties": { "label": "signup" }
    }
  ]
}
```

The project is derived from the authenticated key — client-supplied
ownership fields are ignored. Raw IPs are never stored.

## Response

```json
{
  "ok": true,
  "results": [
    { "index": 0, "id": "evt-01", "status": "accepted" }
  ]
}
```

- `accepted` — stored once (idempotent: replaying the same event ID yields
  `duplicate`, never a second row).
- `rejected` — coarse reason only (`invalid-name`, `invalid-properties`,
  `invalid-timestamp`, `unsupported-type`, `too-large`, `invalid-event`);
  responses never echo submitted properties, keys, or values.

## Envelope errors

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `invalid-envelope` | Content type, JSON, or envelope shape |
| 413 | `too-large` | Request exceeds 512 KiB (enforced while streaming) |
| 429 | `rate-limited` | Per-IP or event-weighted quota exceeded |
| 401 | `unauthorized` | Missing/malformed/wrong bearer key |

## Validation & limits

One envelope version per endpoint major. Batch ≤ 50 events; event ≤ 32 KiB;
names ≤ 128 chars, no control characters; properties strictly JSON-safe
(dangerous keys rejected); depth ≤ 12; strings ≤ 10 000. The SDK enforces
the same ceilings — the server additionally sanitizes credential keys
(`[REDACTED]`) for direct HTTP clients.
