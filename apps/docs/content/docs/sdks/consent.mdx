<SectionLabel label="CONSENT" />

Every v2 client starts in an explicit collection state: `pending`,
`granted`, or `denied`. There is no implicit default — the caller decides.

| State | Behavior |
| --- | --- |
| `pending` | `track()`/`startSession()` return `dropped` results — nothing is queued, nothing is transmitted |
| `granted` | Events queue and deliver (batched, idempotent) |
| `denied` | Like pending, plus a hard stop on everything already collected |

## Withdrawal is effective

```ts
await prism.setCollectionState("denied");
```

Denial is not a label — it acts:

1. the queued events are **cleared** (nothing collected before the
   withdrawal is ever transmitted);
2. the **persisted anonymous ID is deleted** (a later re-grant creates a
   fresh identity — the pre-withdrawal identity is never silently
   restored);
3. the active session is **closed**;
4. in-flight delivery is **cancelled**, and a transport that ignores
   cancellation cannot requeue or redeliver afterwards.

## What consent does NOT change

- Server-side sanitization still applies — direct HTTP clients are
  untrusted regardless of what an SDK claims.
- Retention still operates on the server's own `received_at` clock.
- The write key remains write-only; consent is a client-side policy, the
  server keeps its own abuse protection (per-IP and event-weighted
  quotas).

## Anonymous identity

`anonymousPersistence` controls where the anonymous ID lives: `"none"`
(no identity), `"session"` (client lifetime), or `"persistent"` (survives
launches; requires storage). The ID is never an email, username, or other
personal identifier, and it is cleared on withdrawal.
