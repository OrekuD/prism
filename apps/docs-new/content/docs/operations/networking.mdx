## Default topology

The Compose stack runs everything on an **internal Docker network** with no
default route: containers cannot reach the internet. One service — `web`
(nginx) — is published to the host port (`PUBLIC_PORT`, default 3000) and
proxies `/api` to `api`, `/api/v1/analytics` and `/ws` to `analytics`.

| Direction | Path | Service |
| --- | --- | --- |
| Browser → `web` | `/` | static dashboard |
| Browser → `web` | `/api/*` | product API |
| Browser → `web` | `/api/v1/analytics/*` | ingestion (proxied to analytics) |
| Browser → `web` | `/ws` | realtime WebSocket |
| Browser → `web` | `/files/*` | local storage driver objects |

## Ports

| Port | Binding | Service |
| --- | --- | --- |
| `PUBLIC_PORT` (3000) | host, all interfaces | `web` (nginx) |
| `POSTGRES_PORT` (5432) | **127.0.0.1 only** | `db` |
| sqld (`4001`) | internal network only | `sqld` |
| analytics (`8080`) | internal network only | `analytics` |
| api (`8787`) | internal network only | `api` |

Only `PUBLIC_PORT` needs to be reachable from outside. The database port
binds to loopback for host-side tooling (`pg_dump`).

## Outbound policy

<Callout type="info" title="Note">
The certified CI job builds and exercises the stack with outbound
blocked: health checks, dashboard, SDK ingestion, realtime, and all brand
assets work offline.
</Callout>


The internal network blocks outbound traffic by default. Optional
integrations therefore need explicit allowances (or are simply absent):

| Feature | Requires outbound? | When allowed |
| --- | --- | --- |
| SMTP mail | Yes (TCP 25/465/587) | Configure `MAIL_SMTP_*` |
| Resend mail | Yes (HTTPS) | Configure `RESEND_API_KEY` |
| IP geo enrichment | Yes (HTTPS) | Configure `IP_INFO_API_TOKEN` |
| S3 storage | Yes (HTTPS) | Configure `STORAGE_DRIVER=s3` |
| Social sign-in | Yes (HTTPS) | Configure `GITHUB_*` / `GOOGLE_*` |
| Everything else | **No** | — |

The health checks, dashboard, SDK ingestion, realtime, and all brand assets
work with outbound blocked — the certified CI job builds and exercises the
stack with no external network.

## Proxy / rate limits

- Rate limiters are **in-memory, per-process** (ingestion 120 req/min/IP,
  auth 20 req/min/IP, setup 5/15 min/IP). For multi-replica deployments,
  enforce shared limits at the proxy.
- Put TLS termination in front of `web` — see
  [Reverse proxy & TLS](/docs/self-hosting/operating/reverse-proxy).
- `X-Forwarded-For` is trusted for enrichment and rate limiting (never for
  authorization).
