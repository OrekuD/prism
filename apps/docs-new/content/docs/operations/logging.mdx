All services log to stdout/stderr and rely on the container runtime or your
log collector (docker logs, Loki, etc.).

## What each service logs

| Service | Notable log events |
| --- | --- |
| `api` | Startup config validation failures (with variable names + remediation, **never values**), mail delivery, provisioning warnings, setup-claim lifecycle |
| `analytics` | WebSocket auth warnings (`AUTH_BASE_URL` unconfigured), rate-limit events |
| `migrate` | Each applied migration, with duration |
| `web` | nginx access/error logs (request paths, status codes) |

## What is never logged

- Secrets: `JWT_SECRET_KEY`, `SETUP_TOKEN`, SMTP passwords, API keys are
  **never printed**. Configuration validation messages name the missing
  variable and the remediation command only.
- Session/event payloads: ingestion is not logged at payload level.
- The setup token is compared constant-time and never echoed.

## Reading logs

```sh
docker compose --env-file deploy/compose.env -f deploy/compose.yml logs -f api
docker compose --env-file deploy/compose.env -f deploy/compose.yml logs -f analytics
```

## Redaction

Log redaction of arbitrary user-supplied fields (e.g. event `data`) is
`planned`; today the services log structured operational lines only, and no
pipeline forwards logs off the instance by default (see
[Networking & egress](/docs/operations/networking)).
