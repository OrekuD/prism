<SectionLabel label="WEBSOCKET DELIVERY" />




The Realtime page shows new sessions as map markers the moment they start.
Delivery is push-only over a WebSocket at `/ws` on the analytics API origin.

## Wire protocol

1. Open `wss://<origin>/ws`.
2. Send one message to subscribe:

   ```json
   {
     "type": "connect-project",
     "data": { "projectId": "…", "token": "…" }
   }
   ```

   `token` is a short-lived service JWT issued by the product API (see
   [Authentication](/docs/hosted/authentication)).
3. The server verifies the JWT against `{BASE_URL}/api/auth/jwks`, checks the
   subject is an active user, and checks that user owns or belongs to the
   team that owns the project. Any failure closes the socket.
4. From then on the server pushes:

   ```json
   { "type": "user-connected", "data": { "session": { … } } }
   ```

   for every new session in that project.

Malformed JSON closes the connection. A socket can subscribe to exactly one
project at a time; re-subscribing replaces the previous subscription
idempotently.

## Limits and behavior

- WebSocket upgrades are rate-limited to **30 per minute per client IP**
  (in-memory, per-process).
- A failing socket is dropped silently; it never disrupts delivery to
  healthy clients.
- The map rendering requires a Mapbox access token
  (`VITE_MAPBOX_ACCESS_TOKEN` in the web app's build). Without one, the
  realtime feed still arrives; the map tiles are not loaded.
- Sessions whose `is_online` flag is set are what the map shows; ended
  sessions leave the live view.

## Self-hosted note

The same-origin routing in the default Compose stack exposes `/ws` on the
single public origin, so the dashboard connects with no extra configuration
(see [Reverse proxy & TLS](/docs/self-hosting/operating/reverse-proxy)).
