The Events page lists the **latest 200 events** for a project, newest first:

| Column | Content |
| --- | --- |
| Name | The event name (1–128 characters) |
| Data | The structured JSON payload, pretty-printed |
| Session | The session id the event belongs to |
| Created | Server timestamp |

Events are read from the **analytics store** (sqld/libSQL in self-hosting;
Turso in hosted). If the store is unreachable or unconfigured, the events
list is empty and the rest of the instance keeps working — the product API
reads it through a runtime adapter, so a missing analytics store degrades
reads only.

## Deleting events

There is no event-deletion UI or API today. Retention is bounded by your
analytics store's lifecycle (see [Backup & restore](/docs/self-hosting/operating/backup-restore)
and [Privacy & data](/docs/operations/privacy)).

## Writing events

The dashboard does not write events — that is the SDK's job:

```ts
await prism.logEvent("checkout-started", { value: 42 });
```

See [Events](/docs/sdks/events).
