## Lifecycle

1. **Start** — `POST /api/v1/analytics/sessions` with `userAgent`,
   `referrer`, `location`. The server derives OS, browser, and mobile flag
   from the user agent, inserts the session, and responds
   `{ "sessionId": "…" }`.
2. **Live** — the session is `online` and is pushed to subscribed realtime
   clients as a `user-connected` message.
3. **End** — `POST /api/v1/analytics/sessions/end` with the session id sets
   `is_online = 0`. The update is scoped server-side to the authenticated
   project key, so a key from one project can never end another project's
   session.
4. **Stale** — sessions that never ended are treated as stale server-side;
   the SDK's keepalive/beacon path makes the end reliable for page closes.

## Recorded fields

| Field | Source |
| --- | --- |
| `session_id` | Server-generated UUID |
| `project_id` | Derived from the analytics key |
| `referrer` | Client-supplied (`document.referrer`) |
| `location` | Client-supplied (page path) |
| `os`, `browser`, `is_mobile` | Derived from `userAgent` |
| `country_code`, `lat`, `long` | Best-effort IP enrichment (optional) |
| `ip` | Client IP (never trusted for authorization) |

## IP enrichment

Geo fields are **best-effort and non-blocking**: on any enrichment failure
the session is still recorded with null geo fields. Local development falls
back to a clearly local address (`127.0.0.1`) instead of a hardcoded public
one. The optional `IP_INFO_API_TOKEN` enables richer lookups; without it
enrichment degrades gracefully.

## The session record

The realtime wire format of a session resource includes: `id`, `session_id`,
`project_id`, `referrer`, `country_code`, `os`, `browser`, `location`,
`is_mobile`, `ip`, `lat`, `long`, `is_online`.
